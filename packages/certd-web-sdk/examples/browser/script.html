Script-Ready Browser SDK

사용자가 직접 찾는 HTML5 인증서 선택 화면

국내 인증서 제품들이 공통으로 제공하는 저장매체 선택, 파일 찾기, 선택 결과 확인 흐름을 참고해 구성했습니다. 브라우저는 인증서 저장소를 직접 읽지 못하므로, 사용자가 폴더 또는 파일 4개를 직접 선택하면 SDK가 Go signer WASM으로 NPKI 개인키를 복호화하고 challenge를 서명한 뒤 gateway 실행까지 이어집니다.

Finder Flow

1선택 방식

기본값은 폴더 선택입니다. 브라우저 지원이 제한되면 파일 4개 선택으로 바로 전환할 수 있습니다.

2인증서 찾기
  • `signCert.der`, `signPri.key`, `kmCert.der`, `kmPri.key` 4개가 모두 있어야 합니다.
  • 폴더 선택 시 하위 경로에서 파일명을 기준으로 자동 탐지합니다.
  • 제품 UI에서 흔한 “파일 탐색 / 가져오기” 흐름에 맞춰 검증과 준비를 분리했습니다.
3인증서 정보
4Gateway 실행 설정

이 페이지는 desktop agent 없이 Go/WASM signer로 challenge 서명까지 수행합니다. 다만 저장소 자동 탐색은 불가능하므로 사용자가 파일 또는 폴더를 직접 선택해야 합니다.

대기 중

Result

`Ephemeral 실행`은 challenge 생성, 로컬 서명, gateway 실행까지 한 번에 처리합니다. `Stored 등록`은 challenge 생성 후 서명 결과를 저장형 인증서 등록 API로 보냅니다.

Script Include

실제 배포에서는 아래처럼 글로벌 번들과 같은 디렉터리에 `npki_signer.wasm`, `wasm_exec.js`를 두면 됩니다. 이 예제 페이지는 개발 서버에서 같은 사용감을 내기 위해 글로벌 shim을 먼저 로드합니다. 

<script src="/dist/browser/certd-web-sdk.global.js"></script>
<script>
  const sdk = new CertdWebSdkBrowser.CertdWebSdk({
    gatewayBaseUrl: "/gateway",
    agentBaseUrl: "http://127.0.0.1:8765"
  });
  await sdk.runEphemeralWithBrowserCertificate("org-1", {
    certificateFiles: document.getElementById("html5Files").files,
    password: "certificate-password"
  });
</script>
