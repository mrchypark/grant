Script-Ready Browser SDK

사용자가 직접 찾는 HTML5 인증서 선택 화면

국내 인증서 제품들이 공통으로 제공하는 저장매체 선택, 파일 찾기, 선택 결과 확인 흐름을 참고해 구성했습니다. 브라우저는 인증서 저장소를 직접 읽지 못하므로, 사용자가 폴더 또는 파일 4개를 직접 선택해야 합니다. 이 예제는 `브라우저 전용 challenge 서명`과 `비밀물 escrow 업로드`를 분리해서 보여줍니다.

Finder Flow

1선택 방식

기본값은 폴더 선택입니다. 브라우저 지원이 제한되면 파일 4개 선택으로 바로 전환할 수 있습니다.

2인증서 찾기
  • `signCert.der`, `signPri.key`, `kmCert.der`, `kmPri.key` 4개가 모두 있어야 합니다.
  • 폴더 선택 시 하위 경로에서 파일명을 기준으로 자동 탐지합니다.
  • 여러 인증서 디렉터리를 한 번에 고르면 거부합니다. 한 인증서 번들만 선택해야 합니다.
  • 제품 UI에서 흔한 “파일 탐색 / 가져오기” 흐름에 맞춰 검증과 준비를 분리했습니다.
3인증서 정보
4Gateway 실행 설정

remote gateway는 `https:` 또는 loopback `http:`여야 하고, WASM runtime asset도 same-origin 또는 loopback 에서만 로드됩니다. 예제의 `/gateway`는 현재 origin 아래 경로로 유지됩니다.

대기 중

Result

`Challenge 서명만`은 challenge와 서명 proof만 반환하고 개인키/비밀번호를 업로드하지 않습니다. `Ephemeral 실행 (Escrow)`과 `Stored 등록 (Escrow)`은 서명 후 인증서 번들과 비밀번호를 gateway로 전송합니다.

Script Include

실제 배포에서는 아래처럼 글로벌 번들과 같은 디렉터리에 `npki_signer.wasm`, `wasm_exec.js`를 두면 됩니다. 이 예제 페이지는 개발 서버에서 같은 사용감을 내기 위해 글로벌 shim을 먼저 로드합니다. 

<script src="/dist/browser/certd-web-sdk.global.js"></script>
<script>
  const sdk = new WebSdkBrowser.WebSdk({
    gatewayBaseUrl: "/gateway",
    agentBaseUrl: "http://127.0.0.1:8765"
  });
  const proof = await sdk.createSignedChallengeProof("org-1", {
    certificateFiles: document.getElementById("html5Files").files,
    password: "certificate-password",
    mode: "ephemeral"
  });
</script>
